# Helper suggestions, Spring prefix and init (2026-09-22)

- **Suggest the helper name.** An unresolved key that is a bare, never-reassigned parameter of a named function carries `helperCandidate`; the CLI prints a `customPatterns` snippet, and nothing is attributed until the user declares it. A name shared with a built-in SDK method (`isEnabled`, `variation`, ...) is never suggested: declared, it would bring back the Lombok false positives. On the corpus, suggestions appear only on genuine pass-throughs (`boolVariation`, `getToggle`, ...).
- **Spring `prefix` + `name`.** `@ConditionalOnProperty(prefix = "features", name = "checkout")` reads `features.checkout` as Spring does; an unreadable prefix makes the key unresolved. Without it, `togglz.enabled` and `togglz.console.enabled` collapse into one key `enabled`.
- **`flag-marshal init`** writes a starter `.flagmarshal.yml` with found helpers declared and every policy option commented out. It never overwrites (the Node writer uses `wx`). Tests uncomment the template and validate it, so an example that stops validating fails the build.
