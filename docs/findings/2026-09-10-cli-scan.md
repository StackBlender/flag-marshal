# The first CLI scan (2026-09-10)

Milestone 3. Process-level tests invoke the built CLI as a subprocess and reproduce the `ts-launchdarkly`, `computed-keys` and `no-flags` goldens exactly, proving grammar loading works from `dist/` where module resolution differs from source. A real 30,100-file repository (`../openapi-guard-vscode`) scanned in **0.44s**, correctly skipping `node_modules` and reporting no flags: that repository uses no supported flag SDK.

- **The filesystem port is real.** The core performs no workspace I/O; frontends supply `FileSystem`, so CLI and walker tests run against an in-memory tree.
- **Nested `.gitignore` patterns are scoped to their own directory.** The first implementation added nested patterns to a root-relative matcher, which would have made `web/.gitignore`'s `notes.ts` silently ignore `service/notes.ts`. `test/core/walk.test.ts` pins the case.
- `scanSources` reuses one parser per language across a walk; `scanSource` stays the single-file entry point.
- **Symbolic links are never followed**: a link out of, or back into, the workspace turns a walk infinite.
- **1-based line numbers are a frontend concern**; the contract stores 0-based.
- **Unreadable directories and files are skipped, not fatal.** Real repositories contain broken symlinks and permission-denied paths.
- The standalone binary half of the milestone was deferred: [proposal](../roadmap/proposals/2026-09-10-standalone-binary.md).
